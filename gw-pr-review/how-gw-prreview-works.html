How GW-PRReview Works

A Windows scheduled task that runs a read-only, Claude-powered code review of your teammates' open pull requests (the team roster minus whoever is running it) six times a day, and drops a self-contained HTML report per PR in your Downloads folder for you to validate — it never comments on or approves anything itself.

⏰ Mon–Fri · 6×/day 🔎 Full semantic review 📄 HTML you validate 🔒 Read-only

🚦 Eligibility gate — reviewed only if ALL true

✓
Not a draft
✓
Authored by / assigned to a teammate (roster minus you)
✓
Updated in the last 7 days
✓
You haven't approved it yet
✓
Not reviewed yet — no report exists (1 PR = 1 HTML)
One report per PR. A reviewed PR is skipped — the wrapper won't even launch Claude when there's nothing new. To re-review, delete its HTML from the output folder.

✅

Safety guarantees

🔒 It looks, it never touches

  • No PR writes — never comments, approves, or requests changes on GitHub.
  • No git writes — no branch switch, commit, push, or stash.
  • Only output = HTML reports in Downloads\PR Review\.
  • Verified read-only — the wrapper asserts branch + HEAD are unchanged after each run.
  • gh-gated — aborts cleanly if gh isn't authenticated.
  • No overlap — IgnoreNew + a 90-min lock file.

What you do with a report

① Read the verdict

A color-coded banner (reject / changes / comments / approve) with total error·warning·info counts up top.

② 📋 Copy comment

Each finding gives a ready-to-paste markdown comment (file:line + issue + suggestion + code). Nothing is sent — you paste it into GitHub if you agree.

③ ✕ Dismiss

Hide a finding you disagree with; remembered per PR + SHA in your browser.
