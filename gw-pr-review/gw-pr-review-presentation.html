The problem · Why this matters

The gateway ships fast. Review has to keep up.

The External API gateway grows one GET endpoint at a time, across many domains — Email, CashRegister, ChildCare, Cafeteria, Calendar, Admissions. That's a steady stream of PRs, each needing a real review:

  • Every PR competes for a reviewer's scarce focused time
  • Volume makes it tempting to skim or wave through the routine ones
  • Standards adherence drifts across dozens of similar endpoints
  • A real issue in PR #12 is easy to miss when #13–#18 are also waiting

At this cadence, review is the constraint — not writing the endpoints.

An always-on reviewer that never tires and never skims changes the throughput math.

The method · Five reviewers, batched

Every PR gets five specialists — many PRs at once.

When several PRs are waiting, it reviews them in one run — a recent slot dispatched 10 reviewers across 2 PRs in parallel. Each reviewer reads the whole changed files against its slice of the standard, not a regex over the diff.
